# ホゴネコ — クライアント確認用モック

心とからだを育てる、保護猫との暮らしのブラウザゲーム。

## 実機プレビュー

https://ghbe2.github.io/hogoneko/

GitHub Pages の公開元を `main` ブランチの `/docs` に設定する。
閲覧用パスワードは別途共有。パスワードを知らずにURLを開くと、入口だけが表示される。

これは公開ソースのモック用の簡易閲覧制限であり、機密保護・利用者本人の認証を保証するものではありません。
ゲームのソースはこの公開リポジトリから閲覧・実行できます。公開用のページには暗号化したゲームを格納し、別の無認証ゲームURLは配置しません。

## 更新

ローカル開発は `index.html` を開く。
公開版の生成は、環境変数 `MOCK_VIEW_PASSWORD` に専用の閲覧パスワードを設定してから `node scripts/build-preview.cjs` を実行する。
生成された `docs/` とソースをコミット・プッシュすると、GitHub Pages が更新される。
パスワードはソース・設定ファイル・READMEに記載しない。

セーブはブラウザ内に保存される。PC・スマートフォン・別ブラウザ間では共有されない。

## 公開前の確認（αテストFBの再発防止）

`node scripts/check-release.cjs all` で、進行停止の再発チェックと一連の操作確認をまとめて実行する。
Playwright の Chrome・WebKit が必要。結果は `tests/screenshots/release-check/日時/` に日本語項目名、成功・失敗、ログを保存する。
確認中にソースが変わった場合も成功扱いにしない。

- `critical`：マップの「つぎへ」、餌の選択と操作中断、道具の複数指操作・残留、案内枠の追従、先輩の抱き猫のちらつき。
- `journey`：最初から買い物・家具配置・育成まで、場面転換、譲渡会、メール・プレゼント・アルバム、TNR・帰還、手術画面。
- 保存した状態からの再読み込み、広告中断、二重受取防止も含める。通常操作だけの成功で完了にしない。

既定では現在のローカル本編を確認する。公開候補の `docs/index.html`、公開後のURLも `GAME_URL` で同じテスト対象にできる。
暗号化ページでは `MOCK_VIEW_PASSWORD` を環境変数で渡す。古い公開バージョンの固定URLをテストに使わない。
テスターのセーブを変更せず、独立したブラウザ環境で確認する。

公開の順番は **ローカル確認 → 公開候補を確認 → 保存画像と動作の目視 → 公開 → 配信内容の一致・操作確認**。
320×568、375×812（上部48pxを除くプレイ領域520/764px）を必須とし、報告端末のサイズも追加する。
WebKitの結果はiPhone実機確認の代わりとは表記しない。

タッチの通し確認は `node tests/first-journey-touch.test.cjs`。ボタンはタップ、マップ・餌選択・保護器・家具はブラウザのタッチ入力で実行し、マウスやホイールに代替しない。320×568・375×812で育成開始とアプリ案内まで進め、途中の保存・再読込も確認する。`TOUCH_SIZE=393x659` で報告端末に近いサイズも追加確認できる。文字入力はテストから入力するため、iOSのソフトウェアキーボードは別途実機確認が必要。

`node tests/touch-surfaces.test.cjs` は一覧と家具・写真のタッチ確認。持ち物120カードの描画用ストレス条件、商品一覧、家具一覧と収納・取消・直後の完了、写真一覧30件と左右スワイプ・複数指・キャンセルを2サイズで確認する。スクロールを選択と誤判定しないこと、戻る・閉じるが動かないことも検証する。持ち物の繰り返しカードはテスト専用で、ゲームの所持品や商品には追加しない。

画像は `tests/screenshots/` に保存する。共通ヘルパーを使うテストは同名のJSONに画面、案内ステップ、ボタン位置、残留画像数、実行時エラーも記録する。
動作の前・途中・後を見て、接触位置・柄・余白・タップ位置を確認する。自動テスト通過だけで見た目を合格にしない。
報告は「再現・原因確認」「修正」「自動確認」「目視」「公開確認」を区別する。再現しない報告を解決済みにしない。

`node tests/interruption-recovery.test.cjs` は2サイズで、案内ボタン連打後の必須操作、保護器・家具のフォーカス喪失／ドラッグ途中の再読込、決済連打、報酬連打、広告取消・再読込を確認する。フォーカス喪失はイベントによる検証で、iOSのアプリ切替・OSによる中断を再現したものではない。実機Safari確認は別途必要。
